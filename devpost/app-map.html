Features added after the first build

Real-data dashboard chart

src/components/ui/DashboardChart.tsx plots cumulative started/sent cases per day from real createdAt/sentAt timestamps. The window stretches back to the first case so the curve always rises; date labels thin out on phones and always keep today visible.

Cases manager redesign

src/components/Cases.tsx — card list with status edge colors, a Understand → Draft → Sent → Reply progress track (reads “Done” when finished), filter chips, a custom sort menu, next-step hints, and confirmed delete. Fully Fixora-tokened colors.

Reply decisions: Wait · Clarify · Escalate

src/components/Replies.tsx — Wait shows a next-steps panel; Clarify asks /api/fixora/clarify → draftClarification in src/lib/fixora.ts for an editable itemised question email with a Gmail handoff; Escalate drafts the formal letter as before. decideNextAction in page.tsx records the choice and clears attention.

Detailed chat replies

The system prompt in src/lib/fixora.ts now requires 4–8 sentence explanations (understanding → what it means → why the next question), with an 800-token cap.

Mobile pass

All page CTAs trim to px-3 / py-2 on phones; the Fixora logo shows the full wordmark below sm; filter chips wrap instead of scrolling horizontally.

Reference route: start a conversation

Use this route in the editor while tracing the behavior. It is a reference route; it is not a claim that every stop has been toured interactively yet.

  1. Entry: src/app/page.tsx → startConversation. Creates a case and switches to the conversation screen.
  2. Conversation: src/components/Conversation.tsx → its submit/fetch flow calls /api/fixora and renders streamed assistant text.
  3. Persistence/result: src/lib/storage.ts → upsertCase saves the case; Dashboard.tsx, Cases.tsx, and Replies.tsx show the saved state.
  4. Reply decision: Replies.tsx → onDecision → decideNextAction in page.tsx records the choice; “Request clarification” additionally calls /api/fixora/clarify → draftClarification (Groq) for an editable email draft.

To change this, start here

Change startup/loading behavior

Start at src/app/page.tsx near booted, checkingIntro, and the startup status block.

Change the conversation or questions

Start at src/components/Conversation.tsx for the interaction and src/lib/fixora.ts for the server prompt and response validation.

Change what is saved

Start at src/lib/types.ts for shapes and src/lib/storage.ts for browser persistence.

Change the complaint or reply AI tasks

Start at src/lib/fixora.ts, then inspect src/app/api/fixora/draft/route.ts or src/app/api/fixora/reply/route.ts.

Change the dashboard chart

Start at src/components/ui/DashboardChart.tsx — buildSeries decides the date window and the cumulative started/sent counts; the pills and tooltip live in the same file.

Change reply decisions or the clarification email

Start at src/components/Replies.tsx, decideNextAction in src/app/page.tsx, and draftClarification in src/lib/fixora.ts behind /api/fixora/clarify.

A practice to reuse

Turn a requirement into an observable check. For example, the PRD says the case should remain outside “Waiting for response” until the user confirms sending; the implementation keeps the status transition in src/app/page.tsx and the case status in src/lib/types.ts. On another project, connect the same acceptance criterion to the state transition and then test the visible result.

Run it again

From the project root, run npm install if dependencies are missing, then npm run dev and open http://localhost:3000. Production verification uses npm run lint and npm run build. The Groq-backed paths need GROQ_API_KEY configured in the hosting environment.
