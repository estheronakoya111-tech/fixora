Fixora · reference map

From a confusing problem to a clear next step.

Fixora helps a person explain a billing, payment, delivery, service, or account problem, build a reviewable complaint, and understand the company's response. This is a compact map of the current proof of concept.

One real action through the app

Reference route: start a conversation

Use this route in the editor while tracing the behavior. It is a reference route; it is not a claim that every stop has been toured interactively yet.

  1. Entry: src/app/page.tsx → startConversation. Creates a case and switches to the conversation screen.
  2. Conversation: src/components/Conversation.tsx → its submit/fetch flow calls /api/fixora and renders streamed assistant text.
  3. Persistence/result: src/lib/storage.ts → upsertCase saves the case; Dashboard.tsx, Cases.tsx, and Replies.tsx show the saved state.

To change this, start here

Change startup/loading behavior

Start at src/app/page.tsx near booted, checkingIntro, and the startup status block.

Change the conversation or questions

Start at src/components/Conversation.tsx for the interaction and src/lib/fixora.ts for the server prompt and response validation.

Change what is saved

Start at src/lib/types.ts for shapes and src/lib/storage.ts for browser persistence.

Change the complaint or reply AI tasks

Start at src/lib/fixora.ts, then inspect src/app/api/fixora/draft/route.ts or src/app/api/fixora/reply/route.ts.

A practice to reuse

Turn a requirement into an observable check. For example, the PRD says the case should remain outside “Waiting for response” until the user confirms sending; the implementation keeps the status transition in src/app/page.tsx and the case status in src/lib/types.ts. On another project, connect the same acceptance criterion to the state transition and then test the visible result.

Run it again

From the project root, run npm install if dependencies are missing, then npm run dev and open http://localhost:3000. Production verification uses npm run lint and npm run build. The Groq-backed paths need GROQ_API_KEY configured in the hosting environment.
